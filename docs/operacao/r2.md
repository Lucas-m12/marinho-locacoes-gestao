# Cloudflare R2

Os arquivos (fotos de unidade, dano e checklist, vídeo do teste, documentos de clientes e comprovantes) ficam num bucket **privado** do R2 (ADR 0012). O servidor nunca recebe os bytes: ele assina uma URL de `PUT` para o navegador enviar direto ao bucket e, depois, uma URL de leitura de 10 minutos.

## Buckets

| Ambiente | Bucket |
| --- | --- |
| Desenvolvimento | `marinho-dev` |
| Produção | `marinho-prod` |

Use um bucket separado em desenvolvimento, para que testes nunca toquem nos arquivos reais.

## Variáveis do servidor

Ficam em `apps/server/.env` (desenvolvimento) e no arquivo de ambiente da VPS (produção). Todas são sensíveis e nunca vão para o repositório.

| Variável | De onde vem |
| --- | --- |
| `R2_ACCOUNT_ID` | Painel da Cloudflare → R2 → "Account ID" (aparece na lateral da página do R2) |
| `R2_ACCESS_KEY_ID` | R2 → "Manage R2 API Tokens" → criar token |
| `R2_SECRET_ACCESS_KEY` | Mostrado uma única vez ao criar o token |
| `R2_BUCKET` | `marinho-dev` ou `marinho-prod` |

Crie o token com permissão **Object Read & Write** e restrito ao bucket do ambiente. Um token por ambiente.

## CORS do bucket

O navegador faz o `PUT` direto no R2, então o bucket precisa liberar a origem do front. A regra não é criada por código: configure no painel, em R2 → bucket → **Settings** → **CORS Policy** → **Add CORS policy**, colando este JSON:

```json
[
  {
    "AllowedOrigins": [
      "http://localhost:3001",
      "https://sistema.marinholocacoes.com"
    ],
    "AllowedMethods": ["PUT", "GET"],
    "AllowedHeaders": ["Content-Type"],
    "MaxAgeSeconds": 3600
  }
]
```

- `PUT` é o envio. A URL assinada inclui o `Content-Type` na assinatura, então o navegador precisa mandar exatamente o tipo pedido em `uploads.requestUpload` (o front já usa os `headers` devolvidos).
- `GET` é a leitura pelas URLs de 10 minutos de `files.getDownloadUrl`.
- No bucket de produção, `http://localhost:3001` pode ser removido.

## Como o fluxo confere o arquivo

1. `uploads.requestUpload` valida finalidade, tipo e tamanho (imagem até 10 MB, vídeo até 50 MB, documento até 10 MB), grava o `Upload` como `PENDING` e devolve a URL de `PUT` válida por 10 minutos. A chave é `<finalidade>/<aaaa>/<mm>/<uuid>.<ext>`.
2. O navegador envia o arquivo direto ao R2.
3. `uploads.completeUpload` faz `HEAD` no objeto. Se o tamanho ou o tipo não baterem com o pedido, apaga o objeto e devolve `PRECONDITION_FAILED` (`UPLOAD_INVALID`). Se baterem, marca o `Upload` como `COMPLETED`.
4. Fotos, documentos, mídia do checklist e comprovantes só aceitam upload `COMPLETED`, do próprio usuário e com a finalidade certa.

Uploads que ficam `PENDING` são limpos por uma tarefa agendada (prompt 03).

## Conferir se está funcionando

Com o servidor e o front em modo `http`, envie uma foto de unidade. Se o navegador mostrar erro de CORS no console, confira a regra acima e a origem exata (com `http` ou `https` e sem barra no fim).
